🎯 Objetivo del Análisis

El análisis de conglomerados (clustering) es una técnica exploratoria que busca agrupar casos (personas, países, etc.) en grupos homogéneos llamados clústeres. Los casos dentro de un mismo clúster son similares entre sí, mientras que casos de diferentes clústeres son diferentes.

En este script utilizamos:

  • Distancia de Jaccard: Ideal para variables categóricas (transformadas a binarias)

  • Enlace promedio (UPGMA): Método de clustering que usa el promedio de distancias entre grupos

  • Datos del Latinobarómetro: Para identificar perfiles sociológicos basados en:

  • Ingresos (Deciles)

  • Educación (Básico a Postgrado)

  • Edad (Tramos etarios)

  • Posición política (Izquierda, Centro, Derecha)

📚 Fundamentos Teóricos

¿Qué es la distancia de Jaccard? La distancia de Jaccard mide la disimilitud entre dos casos basándose en la presencia/ausencia de atributos. Se calcula como:

Distancia Jaccard = 1 - (Intersección / Unión)

Donde:

  • Intersección: Número de atributos que ambos casos tienen en común (valor 1 en ambos)

  • Unión: Número total de atributos que al menos uno de los casos tiene

**Ejemplo: Si comparamos dos personas y tenemos 10 categorías posibles:

  • Persona A: Tiene las categorías 1, 3, 5

  • Persona B: Tiene las categorías 1, 5, 7

  • Intersección = {1, 5} → 2 categorías

  • Unión = {1, 3, 5, 7} → 4 categorías

  • Similitud Jaccard = 2/4 = 0.5

  • Distancia Jaccard = 1 - 0.5 = 0.5

¿Qué es el enlace promedio (UPGMA)?

UPGMA significa Unweighted Pair Group Method with Arithmetic Mean. Es un método de clustering que:

  • Calcula la distancia entre dos clusters como el promedio de todas las distancias entre pares de puntos de cada cluster

  • Tiende a producir clusters más equilibrados que otros métodos

  • Es menos sensible a valores atípicos que el enlace simple o completo

🏷️ 3. Convertir Variables a Factores

¿Qué hacemos? Transformamos cada variable a factor, especificando los niveles y su orden.

¿Por qué? Las variables categóricas deben ser tratadas como factores para:

  • Respetar la naturaleza de los datos (no son números continuos)

  • Poder crear las variables binarias (dummies) correctamente

  • Mantener el orden en variables ordinales (educación, edad)

# Convertir cada variable a factor con sus niveles correspondientes
datos_cluster <- datos_cluster %>%
  mutate(
    ingresos     = factor(ingresos, levels = paste("Decil", 1:10)),
    educacion    = factor(educacion, levels = c("Básico","Medio","Técnico",
                                                "Universitario","Postgrado")),
    edad         = factor(edad, levels = c("15-24","25-39","40-54","55-69","70-99")),
    eje_politico = factor(eje_politico, levels = c("Izquierda","Centro","Derecha"))
  )

Interpretación: Ahora R entiende que “Básico” es menor que “Universitario” y que los deciles tienen un orden. Esto es crucial para análisis posteriores.

🔄 4. Transformar a Variables Binarias (Dummies)

¿Qué hacemos? Convertimos las variables categóricas en una matriz de indicadores binarios (0/1), donde cada categoría se convierte en una columna separada.

¿Por qué? La distancia de Jaccard trabaja con datos binarios. Necesitamos representar cada categoría como:

1: La persona pertenece a esa categoría

0: La persona NO pertenece a esa categoría

Ejemplo: Para educación con 5 categorías, cada persona tendrá:

  • Básico: [1,0,0,0,0]

  • Medio: [0,1,0,0,0]

  • Técnico: [0,0,1,0,0]

etc.

# Crear matriz de dummies
# La fórmula ~ ingresos + educacion + edad + eje_politico -1 significa:
# -1 : eliminar el intercepto (columna de 1s que crea por defecto)
X <- model.matrix(~ ingresos + educacion + edad + eje_politico - 1, data = datos_cluster)
X <- as.matrix(X)  # Asegurar que es matriz

# Ver dimensiones
dim(X)  # Filas: número de personas, Columnas: total de categorías

# Ver primeras filas y columnas
head(X[, 1:8])  # Mostramos solo las primeras 8 columnas para no saturar

# Total de categorías por variable
cat("Ingresos:", length(levels(datos_cluster$ingresos)), "categorías\n")
cat("Educación:", length(levels(datos_cluster$educacion)), "categorías\n")
cat("Edad:", length(levels(datos_cluster$edad)), "categorías\n")
cat("Eje político:", length(levels(datos_cluster$eje_politico)), "categorías\n")
cat("TOTAL:", ncol(X), "columnas binarias\n")

Interpretación: Ahora tenemos una matriz donde cada fila es una persona y cada columna es una categoría (ej. “IngresosDecil1”, “EducaciónBásico”, “Edad15-24”, etc.). Los valores son solo 0 o 1.

📐 5. Calcular Distancia de Jaccard

¿Qué hacemos? Calculamos la matriz de distancias entre todas las personas usando la distancia de Jaccard.

¿Por qué? Necesitamos saber qué tan similares o diferentes son las personas entre sí para poder agruparlas.

¿Cómo funciona? Para cada par de personas:

  • Comparamos sus vectores binarios (ej. [1,0,1,0,…] vs [1,1,0,0,…])

  • La distancia será 0 si son idénticas, y se acercará a 1 si son muy diferentes

# Calcular distancia de Jaccard
# binary = TRUE indica que los datos son binarios (0/1)
dist_jaccard <- vegdist(X, method = "jaccard", binary = TRUE)

# Ver la estructura
str(dist_jaccard)  # Es un objeto especial de tipo "dist"

# Convertir a matriz para visualizar
matriz_dist <- as.matrix(dist_jaccard)

# Ver distancias entre las primeras 5 personas
matriz_dist[1:5, 1:5]

# Interpretación: 
# - Diagonal = 0 (una persona es idéntica a sí misma)
# - Valores bajos (ej. 0.2) indican personas similares
# - Valores altos (ej. 0.8) indican personas muy diferentes

vars <- c("ingresos", "educacion", "edad", "eje_politico")
X <- model.matrix(~ . - 1, data = datos_cluster[vars],
                  contrasts.arg = lapply(datos_cluster[vars], contrasts, contrasts = FALSE))
stopifnot(all(X %in% c(0, 1)), all(rowSums(X) == length(vars)))   # 23 columnas 0/1

# Advertencia: con one-hot de 4 variables, Jaccard solo toma 5 valores posibles
sort(unique(round(1 - (0:4) / (8 - (0:4)), 4)))   # 0.0000 0.4000 0.6667 0.8571 1.0000

# Frente a dicha situación la alternativa recomendada para variables categóricas nominales+ordinales es la siguiente:

# d_gower <- cluster::daisy(datos_cluster[vars], metric = "gower")

# hc <- hclust(d_gower, method = "average")

# Verificar que ahora son factores
sapply(datos_cluster, class)

Interpretación: La matriz de distancias es la base para el clustering. Dos personas con distancia cercana a 0 son candidatas a estar en el mismo cluster.

🌲 6. Clustering Jerárquico con Enlace Promedio (UPGMA)

¿Qué hacemos? Aplicamos el algoritmo de clustering jerárquico usando el método de enlace promedio.

¿Cómo funciona el algoritmo?

  • Comienza con cada persona como un cluster individual

  • Encuentra los dos clusters más cercanos (menor distancia)

  • Los fusiona en un nuevo cluster

  • Calcula las distancias entre el nuevo cluster y los demás usando el promedio de distancias

  • Repite hasta que todo queda en un solo cluster

¿Por qué enlace promedio? Es un equilibrio entre:

  • Enlace simple (mínima distancia): Tiende a crear cadenas largas

  • Enlace completo (máxima distancia): Tiende a crear clusters muy compactos

  • Enlace promedio: Más robusto y realista

# Realizar clustering jerárquico
hc <- hclust(dist_jaccard, method = "average")

# Ver qué contiene el objeto hc
names(hc)

# Alturas de fusión (height): distancia a la que se unieron los clusters
# Valores pequeños = uniones tempranas (clusters muy similares)
# Valores grandes = uniones tardías (clusters muy diferentes)
hc$height

# Matriz de fusiones (merge): qué clusters se unieron en cada paso
# Números positivos = clusters formados previamente
# Números negativos = casos individuales
hc$merge

# Interpretación de las primeras fusiones
head(cbind(Paso = 1:6, 
           Fusion = paste(hc$merge[1:6,1], "y", hc$merge[1:6,2]),
           Altura = round(hc$height[1:6], 3)))

Interpretación: El dendrograma (que veremos después) representa visualmente este proceso de fusiones. Las alturas indican qué tan diferentes son los clusters que se unen.

📊 7. Determinar el Número Óptimo de Clústeres

¿Qué hacemos? Evaluamos diferentes números de clusters para elegir el más adecuado.

¿Por qué? El clustering jerárquico no nos dice automáticamente cuántos grupos elegir. Necesitamos un criterio.

Método de la silueta:

Mide qué tan bien clasificado está cada caso

  • Valores cercanos a 1: bien clasificado

  • Valores cercanos a 0: en el borde entre clusters

  • Valores negativos: mal clasificado (quizás en cluster equivocado)

# Calcular silueta para diferentes números de clusters
fviz_nbclust(
  X,                         # Matriz de datos binarios
  FUN = hcut,                 # Función de clustering (jerárquico)
  method = "silhouette",      # Usar método de silueta
  diss = dist_jaccard,         # Usar nuestra matriz de distancia
  k.max = 10                   # Evaluar de 2 a 10 clusters
) +
  geom_vline(xintercept = linetype = 2, color = "red") +
  labs(title = "Método Silhouette para elegir número de clusters",
       subtitle = "Mayor valor = mejor calidad de clustering",
       x = "Número de clusters (k)",
       y = "Ancho promedio de silueta") +
  theme_minimal()

Interpretación:

  • El gráfico muestra el promedio de silueta para cada k

  • Valores más altos indican mejor estructura de clustering

  • La línea roja marca k=5 como posible candidato

  • Debemos equilibrar: alto valor de silueta y clusters interpretables

✂️ 8. Evaluar Diferentes Números de Clústeres

¿Qué hacemos? Probamos varios valores de k para ver cómo se distribuyen los casos.

¿Por qué? El número óptimo según silueta puede no ser el más interpretable. También debemos considerar:

  • Tamaño mínimo de clusters (evitar clusters con 1-2 casos)

  • Interpretabilidad teórica

  • Parsimonia (pocos clusters pero explicativos)

# Probar diferentes números de clusters
k_valores <- c(9, 8, 7, 6, 5)

for (k in k_valores) {
  cat("\n--- k =", k, "---\n")
  clusters_temp <- cutree(hc, k = k)
  print(table(clusters_temp))
}

# Elegir k (justificar según resultados)
k_elegido <- 5
clusters <- cutree(hc, k = k_elegido)

# Ver distribución final
cat("\n✅ Distribución elegida (k =", k_elegido, "):\n")
print(table(clusters))

Interpretación: Buscamos que ningún cluster sea demasiado pequeño (ej. menos del 5% de los casos) y que los tamaños sean relativamente equilibrados.

🌳 10. Visualizar Dendrograma

¿Qué hacemos? Creamos una representación visual del árbol de clustering.

¿Por qué? El dendrograma nos ayuda a entender:

  • La jerarquía de los grupos

  • A qué altura se formaron los clusters

  • Las distancias relativas entre grupos

# Dendrograma básico
fviz_dend(hc, 
          k = k_elegido, 
          rect = TRUE,           # Rectángulos alrededor de clusters
          rect_fill = TRUE,       # Rellenar rectángulos
          rect_border = "jco",    # Colores para rectángulos
          cex = 0.5,              # Tamaño de etiquetas (reducir si muchas)
          color_labels_by_k = TRUE,
          main = paste("Dendrograma - Distancia Jaccard (k =", k_elegido, ")"),
          xlab = "Casos",
          ylab = "Altura (distancia)")

Interpretación del dendrograma:

  • Eje Y (altura): Distancia a la que se unen los clusters

  • Líneas verticales: Cada caso o cluster

  • Líneas horizontales: Fusiones entre clusters

  • Altura de fusión: A mayor altura, más diferentes son los clusters que se unen

  • Rectángulos: Muestran los k clusters elegidos

📈 11. Visualización Alternativa: MDS

¿Qué hacemos? Usamos Escalamiento Multidimensional (MDS) para visualizar los clusters en 2 dimensiones.

¿Por qué? El dendrograma puede ser confuso con muchos casos. MDS nos da una “vista satelital” de los clusters.

# Calcular MDS (reducir a 2 dimensiones)
mds <- cmdscale(dist_jaccard, k = 2)

# Crear data frame para ggplot
mds_df <- data.frame(
  Dim1 = mds[,1],
  Dim2 = mds[,2],
  cluster = datos_cluster$cluster
)

# Graficar
ggplot(mds_df, aes(x = Dim1, y = Dim2, color = cluster)) +
  geom_point(size = 2, alpha = 0.7) +  # Puntos semi-transparentes
  stat_ellipse(aes(group = cluster),   # Elipses de confianza
               level = 0.95, 
               linetype = 2) +
  labs(title = "Visualización MDS de los clusters",
       subtitle = "Distancia Jaccard + enlace promedio (k = 5)",
       x = "Dimensión 1",
       y = "Dimensión 2",
       color = "Cluster") +
  theme_minimal() +
  theme(legend.position = "bottom")

Interpretación del MDS:

  • Puntos cercanos: Casos similares

  • Puntos lejanos: Casos diferentes

  • Elipses: Área donde se concentra cada cluster (95% de los casos)

  • Separación: Si las elipses no se superponen mucho, los clusters están bien definidos

# Función para crear tabla de proporciones clara
tabla_proporciones <- function(var_name) {
  prop <- prop.table(table(datos_cluster$cluster, datos_cluster[[var_name]]), 1) * 100
  prop_df <- as.data.frame.matrix(round(prop, 1))
  prop_df$Cluster <- rownames(prop_df)
  prop_df <- prop_df[, c("Cluster", colnames(prop_df)[-ncol(prop_df)])]
  return(prop_df)
}

# Tablas para cada variable
prop_educ <- tabla_proporciones("educacion")

⚠️ Notas y Advertencias Importantes

1. Sobre la distancia de Jaccard

  • Solo funciona con datos binarios (0/1)

  • No es sensible a dobles ceros (a diferencia de otras distancias)

  • Es ideal para variables categóricas

2. Sobre la estandarización

  • Para Jaccard no se estandariza, porque ya trabajamos con 0/1

  • Si usaras variables numéricas continuas, ahí sí necesitarías estandarizar

3. Sobre la elección de k

  • No hay una respuesta “correcta” única

  • Combinar criterios estadísticos (silhouette) con interpretabilidad teórica

  • Documentar siempre la justificación

4. Sobre la interpretación

  • Los clusters son construcciones del algoritmo, no realidades objetivas

  • Siempre preguntarse: ¿tienen sentido estos grupos?

  • Validar con teoría o conocimiento del dominio
